## Overview

This repository demonstrates a basic DevOps workflow by running a simple HTML web application locally and making it temporarily accessible over the internet through an ngrok tunnel.

It is designed for students, beginners, and developers who want to understand local development, HTTP servers, ports, public URLs, and basic tunneling without deploying an application to a production cloud server.

## Learning Objectives

By completing this tutorial, you will learn how to:

- Run a basic web application on your local machine.
- Understand `localhost`, IP addresses, and TCP ports.
- Use Python's built-in HTTP server.
- Configure and run ngrok on Windows.
- Generate and test a public HTTPS forwarding URL.
- Capture practical evidence for a DevOps assignment.
- Troubleshoot common local server and tunneling issues.

## Prerequisites

Before starting, make sure you have:

- A Windows computer.
- Python 3 installed.
- A web browser such as Google Chrome.
- An ngrok account.
- Git installed if you want to clone or contribute to the repository.

Check Python:

```bat
python --version
```

If necessary, try:

```bat
py --version
```

## Step 1: Get the Project

Clone the repository:

```bash
git clone https://github.com/TawfiqHassan/devops-localhost-ngrok-guide.git
cd devops-localhost-ngrok-guide
```

Alternatively, download the repository as a ZIP file from GitHub and extract it.

## Step 2: Run the Local Web Application

Navigate to the application folder:

```bat
cd app
```

Start Python's built-in HTTP server:

```bat
python -m http.server 8000
```

Alternatively:

```bat
py -m http.server 8000
```

Open the following address in your browser:

**http://localhost:8000**

If the demo page loads, the local server is working.

Keep this terminal open while using the application.

## Step 3: Install and Configure ngrok

Download ngrok from the official website:

https://ngrok.com/download

Create or sign in to your ngrok account:

https://dashboard.ngrok.com/

Follow the dashboard instructions to configure your authentication token. The usual command is:

```bat
ngrok config add-authtoken YOUR_AUTH_TOKEN
```

Replace `YOUR_AUTH_TOKEN` with your actual token. Never publish it in your repository or screenshots.

## Step 4: Expose the Local Application

Open a second terminal window and run:

```bat
ngrok http 8000
```

ngrok will display a forwarding address similar to:

```text
https://your-generated-address.ngrok-free.dev
    -> http://localhost:8000
```

The address shown above is an example. Use the actual URL generated by your ngrok session.

Open the actual HTTPS URL in your browser. If the demo page appears, the tunnel is working.

## Step 5: Understand the Request Flow

```text
Browser on the Internet
          |
          v
Public HTTPS URL (ngrok)
          |
          v
ngrok Tunnel
          |
          v
Local HTTP Server
localhost:8000
          |
          v
app/index.html
```

The local Python server serves the HTML page on port 8000. ngrok provides a public endpoint and forwards incoming requests through its tunnel to the local server.

## Common Problems and Solutions

### 1. Python command is not recognized

Try:

```bat
py --version
```

If Python is not installed, install it from https://www.python.org/downloads/ and ensure Python is added to PATH.

### 2. Port 8000 is already in use

Use another port, such as 8080:

```bat
python -m http.server 8080
```

Then start the matching tunnel:

```bat
ngrok http 8080
```

Both commands must use the same port.

### 3. The public URL is unavailable

Check that:

- The local Python server is running.
- The ngrok session is online.
- The local and forwarding ports match.
- The URL is the current one displayed by ngrok.

### 4. The public URL stops working after closing CMD

The local server and ngrok tunnel are temporary processes. Restart both processes to make the application accessible again. A new ngrok session may generate a different URL.

### 5. The browser shows a 404 for favicon.ico

Browsers may automatically request a favicon. If the main page returns HTTP 200, a missing favicon usually does not prevent the application from working.

## Why Is This Useful in DevOps?

Running applications locally allows developers to validate application behavior before deployment. Exposing a local application through ngrok can help teams demonstrate development builds, test externally delivered webhooks, and collaborate without setting up a production server.

This is a learning demonstration, not a production deployment. A temporary ngrok tunnel should not be treated as a permanent hosting solution.
